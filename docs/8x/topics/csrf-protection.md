## &#10162; CSRF Protection:

CSRF stands for Cross Site Request Forgeries, which are a type of malicious attack or exploit done by unauthorized commands are performed on authenticated user. 

Consider, This can be done by submitting form from malicious website to your current application site. This could cause a trouble. So, it can prevented by using secret value that malicious website does not have for every form submission with POST, PUT, PATCH and DELETE methods. If CSRF token is missing with form submission then Laravel would not proceed further.

### &#10022; Preventing CSRF Requests:

Laravel prevents and protects against CSRF attacks. By assign a CSRF token with user's session, it changes frequently when user's sessions regenerated. So this will be helpful to identify that the user is authenticated and actually makes this request. But the token can't be accessed by malicious applications.

CSRF Token can be accessed using the helper function `csrf_token`.

In `web.php` file:

```php
use Illuminate\Http\Request;
 
Route::get('/token', function (Request $request) {
    $token = $request->session()->token(); // access csrf token
    $token = csrf_token(); // access csrf token

    // ...
});
```

Whenever a form with following methods POST, PUT, PATCH or DELETE has been defined then the form should include a hidden CSRF token field as `_token`. For blade template, use the @csrf directive to generate.

So, this can be validated by CSRF protection middleware, which is `App\Http\Middleware\VerifyCsrfToken`. This middleware included in `web` middleware group by default. Hence, it validate token for each request with session token.

```php
<form method="POST" action="/products">
    @csrf
    <input type="hidden" name="_token" value="{{ csrf_token() }}" /> <!-- equivalent csrf token field -->
</form>
```

### &#10022; Excluding URIs:

For example, When Stripe package to process payments and Which is utilize their webhook system instead of application. Then it need to exclude Stripe webhook handler route from CSRF protection. Because, stripe will not require CSRF token which is sent to the request.

Sometimes, it may require to exclude or ignore CSRF protection. Because, `web` middleware group is applicable to all request. To exclude those routes from outside of the `web` middleware group by using [withoutMiddleware](./middleware.md#-excluding-middleware) method. Or it can be excluded by adding their URIs to the `$except` property of the `VerifyCsrfToken` middleware.

Create another middleware class by extending all of it's properties.

```php
namespace App\Http\Middleware;
 
use Illuminate\Foundation\Http\Middleware\VerifyCsrfToken as Middleware;
 
class VerifyCsrfToken extends Middleware
{
    /**
     * The URIs that should be excluded from CSRF verification.
     *
     * @var array
     */
    protected $except = [
        'stripe/*'
    ];
}
```

**Note:**

- When run a test, CSRF middleware is automatically disabled for all routes.

### &#10022; X-CSRF-Token:

`App\Http\Middleware\VerifyCsrfToken` middleware will check for the `X-CSRF-TOKEN` from request headers in additional to the request parameters. It can be added in `head` section of the `HTML`.

```html
<meta name="csrf-token" content="{{ csrf_token() }}">
```

The CSRF token from meta tag can be used for AJAX request using JavaScript and their plugins.

```js
$.ajaxSetup({
    headers: {
        'X-CSRF-TOKEN': $('meta[name="csrf-token"]').attr('content')
    }
});
```

### &#10022; X-XSRF-Token:

Some JavaScript frameworks and libraries such as Angular and Axios will automatically places the `X-XSRF-TOKEN` header on same-origin requests. By default, the header is automatically send by `resources/js/bootstrap.js` file which includes the Axios HTTP library.

Encrypted XSRF-TOKEN cookie has current CSRF token which is stored by Laravel. That token is included with each response generated by the framework. It can utilized from the cookie value to set the X-XSRF-TOKEN request header.
