## &#10162; Migrations:

-   Migrations act as version control for the database schema.
-   Migrations allow teams to define and share the database schema.
-   Migrations solve the problem of manually updating local database schemas.
-   The Laravel Schema facade provides database-agnostic table creation and manipulation.
-   Migrations use the Schema facade to create and modify database tables and columns.

### &#10022; Generating Migrations:

-   The `make:migration` Artisan command generates database migrations.
-   New migrations are placed in the `database/migrations` directory.
-   Migration filenames contain timestamps for ordering.
    ```bash
    php artisan make:migration create_flights_table
    ```
-   Laravel guesses the table name and creation status from the migration name.
-   If Laravel guesses the table name, the migration file is pre-filled.
-   The table can be specified manually in the migration file.
-   The `--path` option sets a custom migration path relative to the application's base path.
-   Migration stubs can be customized using stub publishing.

### &#10022; Squashing Migrations:

-   Migrations can accumulate and bloat the `database/migrations` directory.
-   Migrations can be `squashed` into a single SQL file.
-   Execute the `schema:dump` command to start squashing.
    ```bash
    php artisan schema:dump
    php artisan schema:dump --prune
    ```
-   Laravel writes a `schema` file to the `database/schema` directory.
-   When migrating, Laravel executes the schema file's SQL first.
-   Remaining migrations not in the schema dump are then executed.
-   Commit the database schema file to source control.
-   Migration squashing is only available for MySQL, PostgreSQL, and SQLite.
-   It utilizes the database's command-line client.
-   Schema dumps cannot be restored to in-memory SQLite databases.

### &#10022; Migration Structure:

-   A migration class contains `up` and `down` methods.
-   `up` method adds tables, columns, or indexes.
-   `down` method reverses operations of the `up` method.
-   Laravel Schema builder creates and modifies tables.
-   Example migration:
    ```php
    use Illuminate\Database\Migrations\Migration;
    use Illuminate\Database\Schema\Blueprint;
    use Illuminate\Support\Facades\Schema;

    class CreateFlightsTable extends Migration
    {
        public function up()
        {
            Schema::create('flights', function (Blueprint $table) {
                $table->id();
                $table->string('name');
                $table->string('airline');
                $table->timestamps();
            });
        }

        public function down()
        {
            Schema::drop('flights');
        }
    }
    ```

**Anonymous Migrations:**

-   Laravel assigns class names to migrations generated by `make:migration`.
-   Anonymous classes can be returned from migration files.
-   Useful for avoiding class name collisions.
    ```php
    use Illuminate\Database\Migrations\Migration;

    return new class extends Migration
    {
        // ...
    };
    ```

**Setting The Migration Connection:**

-   Set the `$connection` property for non-default database connections.
    ```php
    /**
     * The database connection that should be used by the migration.
     *
     * @var string
     */
    protected $connection = 'pgsql';

    public function up()
    {
        // ...
    }
    ```

### &#10022; Running Migrations:

-   The `migrate` Artisan command runs all outstanding migrations.
    ```bash
    php artisan migrate
    ```
-   The `migrate:status` Artisan command shows which migrations have run.
    ```bash
    php artisan migrate:status
    ```

**Forcing Migrations To Run In Production:**

-   Destructive migration operations may cause data loss.
-   Confirmation is prompted before running destructive commands in production.
-   The `--force` flag runs commands without a prompt.
    ```bash
    php artisan migrate --force
    ```

### &#10022; Rolling Back Migrations:

-   The `migrate:rollback` Artisan command rolls back the latest migration operation.
    ```bash
    php artisan migrate:rollback
    ```
-   The `--step` option rolls back a limited number of migrations.
    ```bash
    php artisan migrate:rollback --step=5
    ```
-   The `migrate:reset` command rolls back all migrations.
    ```bash
    php artisan migrate:reset
    ```

**Roll Back & Migrate Using A Single Command:**

-   The `migrate:refresh` command rolls back all migrations and then executes `migrate`.
    ```bash
    php artisan migrate:refresh
    php artisan migrate:refresh --seed
    ```
-   The `--step` option rolls back and re-migrates a limited number of migrations.
    ```bash
    php artisan migrate:refresh --step=5
    ```

**Drop All Tables & Migrate:**

-   The `migrate:fresh` command drops all tables and then executes `migrate`.
    ```bash
    php artisan migrate:fresh
    php artisan migrate:fresh --seed
    ```
-   `migrate:fresh` drops all database tables regardless of their prefix.
-   Use `migrate:fresh` with caution on shared databases.

### &#10022; Create Tables:

-   Use the `create` method on the `Schema` facade to create a new table.
-   `create` accepts the table name and a closure with a `Blueprint` object.
-   Use schema builder column methods to define table columns.
    ```php
    use Illuminate\Database\Schema\Blueprint;
    use Illuminate\Support\Facades\Schema;

    Schema::create('users', function (Blueprint $table) {
        $table->id();
        $table->string('name');
        $table->string('email');
        $table->timestamps();
    });
    ```

**Checking For Table / Column Existence:**

-   Use `hasTable` and `hasColumn` methods to check for table or column existence.
    ```php
    if (Schema::hasTable('users')) {
        // The "users" table exists...
    }

    if (Schema::hasColumn('users', 'email')) {
        // The "users" table exists and has an "email" column...
    }
    ```

**Database Connection & Table Options:**

-   Use the `connection` method for non-default database connections.
    ```php
    Schema::connection('sqlite')->create('users', function (Blueprint $table) {
        $table->id();
        $table->string('username');
    });
    ```
-   The `engine` property specifies the storage engine (MySQL).
    ```php
    Schema::create('users', function (Blueprint $table) {
        $table->engine = 'InnoDB';
        // ...
    });
    ```
-   The `charset` and `collation` properties specify character set and collation (MySQL).
    ```php
    Schema::create('users', function (Blueprint $table) {
        $table->charset = 'utf8mb4';
        $table->collation = 'utf8mb4_unicode_ci';
        // ...
    });
    ```
-   The `temporary` method creates a "temporary" table.
    ```php
    Schema::create('calculations', function (Blueprint $table) {
        $table->temporary();
        // ...
    });
    ```

### &#10022; Update Tables:

-   The `table` method on the `Schema` facade updates existing tables.
-   `table` accepts the table name and a closure with a `Blueprint` instance.
-   Use the `Blueprint` instance to add columns or indexes to the table.
    ```php
    use Illuminate\Database\Schema\Blueprint;
    use Illuminate\Support\Facades\Schema;

    Schema::table('posts', function (Blueprint $table) {
        $table->integer('views');
    });
    ```

### &#10022; Renaming or Dropping Tables:

-   Use the `rename` method to rename an existing table.
    ```php
    use Illuminate\Support\Facades\Schema;

    Schema::rename($from, $to);
    ```
-   Use `drop` or `dropIfExists` methods to drop an existing table.
    ```php
    Schema::drop('users');
    Schema::dropIfExists('users');
    ```

**Renaming Tables With Foreign Keys:**

-   Explicit name the foreign key constraints in migrations before renaming tables.
-   This prevents foreign key constraint names from referencing the old table name.

### &#10022; Create Columns:

-   The `table` method on the `Schema` facade updates existing tables and adds columns.
-   `table` takes the table name and a closure with an `Illuminate\Database\Schema\Blueprint` instance.
-   Use the `Blueprint` instance to add columns to the table.
    ```php
    use Illuminate\Database\Schema\Blueprint;
    use Illuminate\Support\Facades\Schema;

    Schema::table('posts', function (Blueprint $table) {
        $table->integer('views');
    });
    ```

### &#10022; Column Modifiers:

-   Column modifiers alter column behavior.
-   Example: `nullable()` makes a column accept `NULL` values.
    ```php
    use Illuminate\Database\Schema\Blueprint;
    use Illuminate\Support\Facades\Schema;

    Schema::table('users', function (Blueprint $table) {
        $table->string('email')->nullable();
    });
    ```

**Available Column Modifiers:**

| Modifier | Description |
|---|---|
| `->after('column')` | Place the column "after" another column (MySQL). |
| `->autoIncrement()` | Set `INTEGER` columns as auto-incrementing (primary key). |
| `->charset('utf8mb4')` | Specify a character set for the column (MySQL). |
| `->collation('utf8mb4_unicode_ci')` | Specify a collation for the column (MySQL/PostgreSQL/SQL Server). |
| `->comment('my comment')` | Add a comment to a column (MySQL/PostgreSQL). |
| `->default($value)` | Specify a "default" value for the column. |
| `->first()` | Place the column "first" in the table (MySQL). |
| `->from($integer)` | Set the starting value of an auto-incrementing field (MySQL / PostgreSQL). |
| `->invisible()` | Make the column "invisible" to `SELECT *` queries (MySQL). |
| `->nullable($value = true)` | Allow `NULL` values to be inserted into the column. |
| `->storedAs($expression)` | Create a stored generated column (MySQL / PostgreSQL). |
| `->unsigned()` | Set `INTEGER` columns as `UNSIGNED` (MySQL). |
| `->useCurrent()` | Set `TIMESTAMP` columns to use `CURRENT_TIMESTAMP` as default value. |
| `->useCurrentOnUpdate()` | Set `TIMESTAMP` columns to use `CURRENT_TIMESTAMP` when a record is updated. |
| `->virtualAs($expression)` | Create a virtual generated column (MySQL / PostgreSQL / SQLite). |
| `->generatedAs($expression)` | Create an identity column with specified sequence options (PostgreSQL). |
| `->always()` | Defines the precedence of sequence values over input for an identity column (PostgreSQL). |
| `->isGeometry()` | Set spatial column type to geometry - the default type is geography (PostgreSQL). |

**Default Expressions:**

-   `default` modifier accepts a value or an `Illuminate\Database\Query\Expression` instance.
-   `Expression` prevents Laravel from quoting the value, allowing database-specific functions.
-   Example: Default value for a JSON column.
    ```php
    use Illuminate\Support\Facades\Schema;
    use Illuminate\Database\Schema\Blueprint;
    use Illuminate\Database\Query\Expression;
    use Illuminate\Database\Migrations\Migration;

    class CreateFlightsTable extends Migration
    {
        public function up()
        {
            Schema::create('flights', function (Blueprint $table) {
                $table->id();
                $table->json('movies')->default(new Expression('(JSON_ARRAY())'));
                $table->timestamps();
            });
        }
    }
    ```
-   Default expression support depends on the database driver, version, and field type.

**Column Order:**

-   The `after` method adds columns after an existing column (MySQL).
    ```php
    $table->after('password', function ($table) {
        $table->string('address_line1');
        $table->string('address_line2');
        $table->string('city');
    });
    ```

### &#10022; Modifying Columns:

**Prerequisites:**

-   Install the `doctrine/dbal` package using Composer.
    ```bash
    composer require doctrine/dbal
    ```
-   For `timestamp` method columns, add configuration to `config/database.php`.
    ```php
    use Illuminate\Database\DBAL\TimestampType;

    'dbal' => [
        'types' => [
            'timestamp' => TimestampType::class,
        ],
    ],
    ```
-   For Microsoft SQL Server, install `doctrine/dbal:^3.0`.

### &#10022; Update Column Attributes:

-   The `change` method modifies the type and attributes of existing columns.
-   Example: Increase the size of a string column.
    ```php
    Schema::table('users', function (Blueprint $table) {
        $table->string('name', 50)->change();
    });
    ```
-   Example: Modify a column to be nullable.
    ```php
    Schema::table('users', function (Blueprint $table) {
        $table->string('name', 50)->nullable()->change();
    });
    ```
-   Modifiable column types: `bigInteger`, `binary`, `boolean`, `date`, `dateTime`, `dateTimeTz`, `decimal`, `integer`, `json`, `longText`, `mediumText`, `smallInteger`, `string`, `text`, `time`, `unsignedBigInteger`, `unsignedInteger`, `unsignedSmallInteger`, and `uuid`.
-   Modifying timestamp columns requires a registered Doctrine type.

### &#10022; Rename Columns:

-   Use the `renameColumn` method to rename a column.
-   Ensure `doctrine/dbal` is installed via Composer.
    ```php
    Schema::table('users', function (Blueprint $table) {
        $table->renameColumn('from', 'to');
    });
    ```
-   Renaming `enum` columns is not supported.

### &#10022; Dropping Columns:

-   Use the `dropColumn` method to drop a column.
-   For SQLite, install `doctrine/dbal` via Composer before using `dropColumn`.
    ```php
    Schema::table('users', function (Blueprint $table) {
        $table->dropColumn('votes');
    });
    ```
-   Drop multiple columns by passing an array of column names to `dropColumn`.
    ```php
    Schema::table('users', function (Blueprint $table) {
        $table->dropColumn(['votes', 'avatar', 'location']);
    });
    ```
-   Dropping or modifying multiple columns in a single migration is not supported for SQLite.

**Available Command Aliases:**

| Command                         | Description                                 |
|---------------------------------|---------------------------------------------|
| `$table->dropMorphs('morphable');` | Drop the `morphable_id` and `morphable_type` columns. |
| `$table->dropRememberToken();`    | Drop the `remember_token` column.            |
| `$table->dropSoftDeletes();`      | Drop the `deleted_at` column.                 |
| `$table->dropSoftDeletesTz();`    | Alias of `dropSoftDeletes()` method.        |
| `$table->dropTimestamps();`       | Drop the `created_at` and `updated_at` columns. |
| `$table->dropTimestampsTz();`     | Alias of `dropTimestamps()` method.          |

### &#10022; Create Indexes:

-   Laravel schema builder supports various index types.
-   Example: Create a unique index on the `email` column.
    ```php
    use Illuminate\Database\Schema\Blueprint;
    use Illuminate\Support\Facades\Schema;

    Schema::table('users', function (Blueprint $table) {
        $table->string('email')->unique();
    });
    ```
-   Alternatively, create the index after defining the column.
    ```php
    $table->unique('email');
    ```
-   Create compound (composite) indexes by passing an array of columns.
    ```php
    $table->index(['account_id', 'created_at']);
    ```
-   Specify the index name as the second argument.
    ```php
    $table->unique('email', 'unique_email');
    ```

**Available Index Types:**

| Command | Description |
|---|---|
| `$table->primary('id');` | Adds a primary key. |
| `$table->primary(['id', 'parent_id']);` | Adds composite keys. |
| `$table->unique('email');` | Adds a unique index. |
| `$table->index('state');` | Adds an index. |
| `$table->fulltext('body');` | Adds a fulltext index (MySQL/PostgreSQL). |
| `$table->fulltext('body')->language('english');` | Adds a fulltext index of the specified language (PostgreSQL). |
| `$table->spatialIndex('location');` | Adds a spatial index (except SQLite). |

**Index Lengths & MySQL / MariaDB:**

-   Laravel uses `utf8mb4` character set by default.
-   Older MySQL/MariaDB versions may require manual configuration of default string length.
-   Configure default string length in `App\Providers\AppServiceProvider`'s `boot` method.
    ```php
    use Illuminate\Support\Facades\Schema;

    public function boot()
    {
        Schema::defaultStringLength(191);
    }
    ```
-   Alternatively, enable `innodb_large_prefix` option for your database.

### &#10022; Rename Indexes:

-   Use the `renameIndex` method to rename an index.
-   The method takes the current index name and the desired name as arguments.
    ```php
    $table->renameIndex('from', 'to');
    ```

### &#10022; Drop Indexes:

-   Specify the index's name to drop it.
-   Laravel generates index names based on table, column, and index type.

**Examples:**

| Command | Description |
|---|---|
| `$table->dropPrimary('users_id_primary');` | Drop a primary key from the "users" table. |
| `$table->dropUnique('users_email_unique');` | Drop a unique index from the "users" table. |
| `$table->dropIndex('geo_state_index');` | Drop a basic index from the "geo" table. |
| `$table->dropSpatialIndex('geo_location_spatialindex');` | Drop a spatial index from the "geo" table (except SQLite). |

-   Passing an array of columns to a drop index method generates the conventional index name.
    ```php
    Schema::table('geo', function (Blueprint $table) {
        $table->dropIndex(['state']); // Drops index 'geo_state_index'
    });
    ```

### &#10022; Foreign Key Constraints:

-   Laravel supports creating foreign key constraints for referential integrity.
-   Example: `user_id` column in `posts` table referencing `id` in `users` table.
    ```php
    use Illuminate\Database\Schema\Blueprint;
    use Illuminate\Support\Facades\Schema;

    Schema::table('posts', function (Blueprint $table) {
        $table->unsignedBigInteger('user_id');

        $table->foreign('user_id')->references('id')->on('users');
    });
    ```
-   Shorter syntax using `foreignId` and `constrained` methods.
    ```php
    Schema::table('posts', function (Blueprint $table) {
        $table->foreignId('user_id')->constrained();
    });
    ```
-   `foreignId` creates `UNSIGNED BIGINT`, `constrained` uses conventions for table and column names.
-   Specify table name if it doesn't match conventions.
    ```php
    Schema::table('posts', function (Blueprint $table) {
        $table->foreignId('user_id')->constrained('users');
    });
    ```
-   Specify "on delete" and "on update" actions.
    ```php
    $table->foreignId('user_id')
        ->constrained()
        ->onUpdate('cascade')
        ->onDelete('cascade');
    ```
-   Alternative, expressive syntax for actions:

| Method | Description |
|---|---|
| `$table->cascadeOnUpdate();` | Updates should cascade. |
| `$table->restrictOnUpdate();` | Updates should be restricted. |
| `$table->cascadeOnDelete();` | Deletes should cascade. |
| `$table->restrictOnDelete();` | Deletes should be restricted. |
| `$table->nullOnDelete();` | Deletes should set foreign key to null. |

-   Additional column modifiers must be called before `constrained`.
    ```php
    $table->foreignId('user_id')
        ->nullable()
        ->constrained();
    ```

**Dropping Foreign Keys:**

-   Use `dropForeign` method, passing the foreign key constraint name.
-   Foreign key constraint names follow the same convention as indexes.
    ```php
    $table->dropForeign('posts_user_id_foreign');
    ```
-   Pass an array containing the column name to `dropForeign`.
    ```php
    $table->dropForeign(['user_id']);
    ```

**Toggling Foreign Key Constraints:**

-   Enable/disable foreign key constraints using:
    ```php
    Schema::enableForeignKeyConstraints();
    Schema::disableForeignKeyConstraints();
    ```
-   SQLite disables foreign key constraints by default.
-   Enable foreign key support in SQLite configuration.
-   SQLite supports foreign keys only on table creation, not alteration.

### &#10022; Events:

-   Migration operations dispatch events for convenience.
-   All events extend `Illuminate\Database\Events\MigrationEvent`.

**Event Classes:**

| Class | Description |
|---|---|
| `Illuminate\Database\Events\MigrationsStarted` | A batch of migrations is about to be executed. |
| `Illuminate\Database\Events\MigrationsEnded` | A batch of migrations has finished executing. |
| `Illuminate\Database\Events\MigrationStarted` | A single migration is about to be executed. |
| `Illuminate\Database\Events\MigrationEnded` | A single migration has finished executing. |
